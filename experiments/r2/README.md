## 一、背景与风险假设

B3 实验（已完结，单模型基线）对比了两种词表：
- **条件 A**（af-mobile 现状）：`signal/computed/effect/batch` + `html\`\`` 返回**字符串** + 手动 DOM 操作（getElementById / addEventListener / innerHTML）
- **条件 B**（k 框架）：`html\`\`` 返回**真实 DOM**（四种绑定）+ `Show/For/Switch` 控制流 + `render/clean`

B3 结果（单模型）：条件 B 会话成本降约 24%（75.8%），代码 token 降 23%（76.9%），5 任务仅 1 个需返工（t4，2 轮通过）。

**R2 风险**：k 词表是自定义新词表，**不在任何模型的训练分布内**。模型可能把它与训练数据中的相近框架（lit-html / Solid / Vue）混淆，导致：
1. **词表幻觉**：调用词表卡未定义的 API（如 `on:click`、`use:`、`class:`、`createSignal`、`.value`）
2. **词表回避**：不信任词表，绕开用原生 DOM 手写（失去 B3 成本优势）
3. **返工增多**：一次通过率下降，返工轮数抵消 token 节省

**判定假设**：
- H1（R2 成立）：任一模型条件 B 一次通过率 < 条件 A − 20 个百分点，或幻觉任务占比 > 20%
- H2（R2 推翻）：全部模型 B/A 会话成本比 ≤ 85% 且一次通过率差 ≤ 10 个百分点

## 二、实验设计

2（词表条件）× 5（任务）× N（模型），被试内设计。**每模型 2 个会话**（A 一个、B 一个，每会话含全部 5 任务）。

| 项 | 说明 |
|---|---|
| 被试模型 | ≥4 个异构家族（见第三节），B3 已测模型作基线不必重测 |
| 会话独立性 | 每条件独立新会话；两条件不得同会话；模型间不得共享上下文 |
| 顺序平衡 | 第 1、3 个模型先 A 后 B；第 2、4 个先 B 后 A（防顺序效应） |
| 返工协议 | 评分失败 → 把评分器输出原文贴回**同会话**让模型修复，直到全过或达 3 轮上限；计返工轮数 |

## 四、环境准备（一次性，约 10 分钟）

```bash
# 本目录（experiments/r2/）内执行
npm install          # 装 @af-mobile/ui（条件 A 运行时）+ jsdom（评分器）
mkdir -p results     # 各模型结果按 results/<模型名>/ 存放
```

文件清单：
- `prompts/promptA.md`：条件 A 词表卡（粘贴给模型）
- `prompts/promptB.md`：条件 B 词表卡（粘贴给模型）
- `prompts/tasks.md`：任务卡（两条件共用，粘贴给模型）
- `runtime/k-flow.js`：条件 B 运行时（评分器自动装配，无需手动处理）
- `run.mjs`：确定性评分器
- `tokens.mjs`：可选 token 统计（需 `npm i -D gpt-tokenizer`）
- `fixtures/`：评分器自检夹具（两臂各一个 t1 参考解，验证装配路径，不作为实验数据）
- `skills/af-mobile-r2/SKILL.md`：单模型采集 SOP（调度式/自管式，供不同模型家族的新会话执行）

**评分器自检（采集前跑一次，确认基础设施正常）**：
```bash
node run.mjs A t1 fixtures/solA    # 期望：PASS + 断言 5/5
node run.mjs B t1 fixtures/solB    # 期望：PASS + 断言 5/5（自动装配 k-flow.js）
```

## 五、采集流程（每模型约 30 分钟）

### 步骤 1 — 新建会话，粘贴条件词表卡
新建空白会话，粘贴 `prompts/promptA.md` **或** `prompts/promptB.md` 全文。
不要附加任何解释、提示词工程或额外示例——两个条件除词表卡外必须完全同等待遇。

### 步骤 2 — 追加任务卡
同一会话继续粘贴 `prompts/tasks.md` 全文（含接口契约与输出要求）。

### 步骤 3 — 保存生成代码
模型输出 5 个文件（t1.mjs ~ t5.mjs）。保存到：
```bash
results/<模型名>/solA/t1.mjs ... t5.mjs   # 条件 A 会话
results/<模型名>/solB/t1.mjs ... t5.mjs   # 条件 B 会话
```
只保存代码文件本身（剥掉 markdown 代码围栏），不要手工修改内容。

### 步骤 4 — 评分
```bash
node run.mjs A all results/<模型名>/solA   # 条件 A
node run.mjs B all results/<模型名>/solB   # 条件 B（自动装配 k-flow.js）
```

### 步骤 5 — 返工（如有失败任务）
把评分器输出**原文**贴回同会话，追加一句：「以下是自动化测试输出，请修复失败项，只输出修改后的完整文件」。
保存修复后的文件，重新评分。重复直到全过或达 3 轮上限。每轮计一次返工。

### 步骤 6 — 记录指标
按第七节模板填写。两条件都完成后，换下一个模型（注意顺序平衡）。

## 六、指标定义与采集

| 指标 | 定义 | 采集方式 |
|---|---|---|
| 一次通过率 | 首轮评分全断言通过的任务数 / 5 | run.mjs SUMMARY 行 |
| 返工轮数 | 每任务通过前的返工次数（上限 3） | 人工计数 |
| 会话输出 tokens | 该会话模型生成的全部内容 token 数（含返工轮） | 模型端 usage 统计 |
| 代码 tokens | 5 个 .mjs 文件 token 总数 | `node tokens.mjs results/<模型>/solA results/<模型>/solB`（可选标准化） |
| 词表幻觉任务数 | 出现幻觉 API 的任务数（见下） | 人工检查代码 |
| 词表回避任务数 | 绕开词表用原生 DOM 完成可由词表完成的任务数 | 人工检查代码 |

**词表幻觉判定**（人工检查，逐任务）：
- 条件 B 幻觉：出现词表卡 10 词之外的**框架级** API。典型：`on:click`、`use:`、`class:`、`style:`（Solid 写法）、`createSignal`、`createEffect`（Solid）、`.value`（Vue ref）、`ref=${}`、`html.set()`、`render()` 参数顺序颠倒等
- 条件 A 幻觉：出现词表卡之外的 API 当作 af-mobile 导入，如 `ref()`、`watch()`、`onMounted()`、`reactive()`
- 原生 DOM API（querySelector、createElement、addEventListener 等）**不算幻觉**——它是两条件都允许的基础设施

**词表回避判定**（仅条件 B）：任务的核心 UI 逻辑（列表渲染、条件渲染、双向绑定）完全未用 k 词表实现（如用 innerHTML 字符串拼接 + 手动事件做列表），算回避 1 个任务。

## 八、防污染与公平性规则

1. **不得告知实验目的**：不向模型提及"实验""对比""k 框架是新词表"等元信息
2. **两条件同等待遇**：除词表卡不同外，粘贴内容、追加说明、返工提示语逐字相同
3. **不手工修码**：保存时只剥代码围栏；发现 bug 也走返工协议让模型自己修
4. **禁用工具/联网**：若模型有 web search 或代码执行工具，关闭之，纯文本生成
5. **同一会话内顺序**：任务按 t1→t5 顺序呈现（与会话内学习效应一致，两条件可比）

## 九、判定标准（全部模型回收后）

> **v3 轮口径变更（2026-08-27 登记）**：主判从「全部模型成本比 ≤85% 一票否决」改为「**pooled 净节省 ≥15% 主判 + 单家族超 85% 标记风格离群值**」。理由：v1→v2 分解证明轮间差异主要来自卡而非模型（A 卡缺陷伪影贡献 8.4pp）；单家族 n=1 的 code 风格噪声（A 代码降幅 −3% ~ −16%）使「全部 ≤85%」对卡质量变化不敏感。次判：**价格加权口径**（卡×1 输入价 + 代码×4 输出价），报告用、不参与主判，保持与 v1/v2/B3 的 token 口径可比性。
>
> **v3 轮作废（2026-08-27 晚间追加，详见 results/summary.md「v3 轮作废重登记」）**：v3 五「家族」实为同一 GLM-5.3 会话五连跑（子代理模型随会话而非随标签），家族标签全部无效。GLM 五跑测得单跑会话比噪声地板 SD≈5.2pp → **本节「≥15%」主判线在每家族 n=1 的设计下统计功效不足（不可判）**；若按 D-006 选项乙重采，须每家族 ≥2 跑并改用配对区间判定。跨模型结论以 v2 轮为准。

| 结果 | 判定 | 后续动作 |
|---|---|---|
| pooled B/A 净节省 ≥ 15% 且单家族幻觉 ≤ 20% | H2 成立，R2 解除 | k 词表可进入落地评估 |
| 部分模型幻觉任务 > 20% 或 B 通过率显著低 | H1 成立（部分） | 词表卡加 few-shot 反例后再测一轮 |
| 成本优势消失（净节省 ≈ 0）且无幻觉 | 词表中性 | 仅按工程价值决策，不依赖 AI 成本论据 |
