## 备注（幻觉 API 明细、回避任务明细、异常情况）

### MiniMax-M3（2026-08-27，调度式子代理采集）

- **采集方式**：主代理（MiniMax-M3，已接触 k 材料不可作被试）派两个零上下文子代理分别作 A/B 臂被试；被试提示词仅内联各自词表卡 + 任务卡原文 + 禁用工具。顺序平衡：MiniMax-M3 为 R2 第 5 个招募家族 → **先 A 后 B**（奇数序）。
- **A 臂首轮 5/5 全 PASS（零返工）**：被试正确使用 `el.innerHTML = html\`...\`` 创建 DOM，现状词表 API 使用规范，零幻觉、零回避。t5 用 `errEl.textContent = bad ? '邮箱格式错误' : ''` + style.display 联动，正确避免"隐藏元素文本仍在 DOM"陷阱。
- **B 臂首轮 5/5 全 PASS（零返工）**：与 Seed-Code 共同成为 R2 首批两臂首轮全过、零返工的模型。k 词表 API 使用规范（signal/computed/effect/For/Show/batch 均正确），零幻觉、零回避。
- **代码风格亮点**：
  - t2 用 `data-i` 属性记录索引实现点击删除，避开了其他模型的"通过 indexOf 重建索引"做法，更稳定。
  - t3 错误捕获中加 `try { ... } catch (err) { ... }` 保留了错误对象（虽然未使用），符合防御式编程。
  - t4 搜索时用 `data.slice()` 拷贝避免外部引用修改（其他模型直接返回原数组引用，被试者更严谨）。
- **B 臂风格亮点（非幻觉，属风格选择）**：
  - t3 用 `batch(() => { ... })` 把 pending 态的三个 set 合并为一次通知，是 R2 首批正确使用 batch 的模型，体现对词表卡 batch 语义的理解。
  - t2/t3/t4 用 `${() => For({ ... })}` 包裹 For（For 本身已返回响应式节点，包裹不冗余也无副作用），显示被试倾向用函数子位明确意图。
- **会话 tokens 无法采集**：子代理无 usage 统计，记"—"。代码 token：A 1360 / B 958（tokens.mjs），**B/A = 70.4%**——R2 目前最低，显著 <85% 阈值。词表卡 token 560/445 与 B3 一致。
- **异常**：无。A 臂首轮 5/5 与 Seed-Code 同为 R2 A 臂最佳首轮成绩；B 臂首轮 5/5 与 Seed-Code 持平。MiniMax-M3 是 R2 表现最稳定的模型之一。

### Seed-Code（2026-08-27，调度式子代理采集）

- **采集方式**：主代理（已接触 k 材料不可作被试）派两个零上下文子代理分别作 A/B 臂被试；被试提示词仅内联各自词表卡 + 任务卡原文 + 禁用工具。顺序平衡：Seed-Code 为 R2 第 4 个招募家族 → **先 B 后 A**（偶数序）。
- **首次两臂首轮全 PASS**：Seed-Code 是 R2 目前**首个两臂首轮全过、零返工**的模型（baseline B3 B 臂有 t4 返工，其余三模型均有 t5/A 臂首轮 0/5 问题）。t5 处理方式：A 臂用 `errEl.textContent = valid ? '' : '邮箱格式错误'`；B 臂用 `Show({ when: () => !emailValid() })` 条件渲染错误节点——均正确避免"隐藏元素文本仍在 DOM"陷阱。
- **B 臂风格亮点（非幻觉，属风格选择）**：
  - 所有任务用 `render(() => html\`...\`, el)` 而非 `el.appendChild` —— render 是 k 词表 10 词之一，合法使用。render 语义是 replaceChildren，对 mount 来说是合理的"清空并填充"模式。
  - t3 用 **Switch** 实现异步五态（pending/success/error/empty/def），词表卡 10 词含 Switch，属词表原生能力，比其他模型的 if/else 效果更声明式。
  - t4/t5 用 `.prop=${kw/.prop=${name}}` 把 signal 直绑 input.value——词表卡明确列出 DOM 属性绑定含 `.prop=`，合法。但绑定 getter 值写回时不会触发 input 事件，需配合 `@input` 手动同步，被试正确处理。
- **A 臂风格**：中规中矩，正确用 `el.innerHTML = html\`...\`` 创建 DOM，effect 驱动 textContent 更新，列表用 `items.map(...).join('')`，完全符合现状词表惯用法。t3 用 4 个独立 signal（loading/loaded/items/error）而不是单一状态对象，逻辑正确但略冗余。
- **幻觉/回避**：两臂均为零。
- **会话 tokens 无法采集**：子代理无 usage 统计，记"—"。代码 token：A 1373 / B 1011（tokens.mjs），**B/A = 73.6%**，与 GLM-5.3 并列最低。A 行数显著多于其他模型（177 vs 其他 75-98），t3 多信号设计是主要贡献者。词表卡 token 560/445 与 B3 一致。

### Qwen3.7-plus（2026-08-27，调度式子代理采集）

- **采集方式**：主代理（Qwen3.7-plus，已接触 k 材料不可作被试）派两个零上下文子代理分别作 A/B 臂被试；被试提示词仅内联各自词表卡 + 任务卡原文 + 禁用工具。顺序平衡：Qwen 为 R2 第 3 个招募家族 → **先 A 后 B**（奇数序）。
- **A 臂首轮 0/5 全 FAIL（返工 1 轮修复）**：所有任务根因一致——被试未先 `el.innerHTML = ...` 创建 DOM 就直接 `el.querySelector('#c')` 等，元素不存在返回 null，导致 `Cannot set properties of null`。这是接口契约（`mount(el)` 负责在 `el` 内创建所有需要的 DOM 元素）的理解偏差，非 API 幻觉。返工提示中补充了"关键：`mount(el)` 负责在 `el` 内创建所有需要的 DOM 元素"，被试 1 轮修复。
- **B 臂首轮 5/5 全 PASS（零返工）**：被试正确使用 `el.appendChild(html\`...\`)` 创建 DOM，k 词表 API 使用规范（signal/computed/effect/Show/For 均正确），零幻觉、零回避。t5 用 `Show({ when: () => email() && !valid(), kids: ... })` 条件渲染错误信息，避免了前两模型 t5 的 `hidden` 陷阱。
- **会话 tokens 无法采集**：子代理无 usage 统计，记"—"。代码 token：A 1092 / B 940（tokens.mjs），**B/A = 86.1%**，略高于 85% 阈值，是 R2 目前最高的代码 token 比（GLM 73.6%、DeepSeek 77.4%）。词表卡 token 560/445 与 B3 一致。
- **异常**：A 臂首轮 0/5 是 R2 目前最差首轮流成绩（GLM 4/5、DeepSeek 4/5），但 B 臂首轮 5/5 全 PASS 是 R2 目前最佳首轮流成绩。两臂表现反差极大，提示 Qwen3.7-plus 对"mount(el) 负责创建 DOM"这一隐含契约的理解在条件 A（现状词表）下弱于条件 B（k 词表），可能与 k 词表更声明式、更接近训练分布有关。

### DeepSeek-V4（2026-08-27，调度式子代理采集）

- **采集方式**：主代理（DeepSeek-V4-Flash，已接触 k 材料不可作被试）派两个零上下文子代理分别作 A/B 臂被试；被试提示词仅内联各自词表卡 + 任务卡原文 + 禁用工具（防检索仓库破坏闭卷）。顺序平衡：DeepSeek 为 R2 第 2 个招募家族 → **先 B 后 A**（偶数序）。两会话子代理均为新鲜零上下文，闭卷条件成立。
- **A/B 臂 t5 失败明细（各返工 1 轮，失败根因两臂相同）**：`#err` 先静态内联"邮箱格式错误"，仅依邮箱合法性切换 `hidden`/属性——`hidden` 元素文本仍留在 DOM textContent，导致合法邮箱时 `!text.includes('邮箱格式错误')` 断言失败（"合法邮箱无错误"、"改回合法错误消失"）。返工思路两臂一致：B 臂改 `hidden=${invalid}` 属性绑定 + 子位条件文本；A 臂改 `err.textContent = valid ? '' : '邮箱格式错误'`。**与 GLM-5.3 A 臂 t5 失败模式完全相同**（B3 基线 t4 返工点则不同），提示该断言对"错误文本随状态彻底消失"敏感，是两模型共同易错点。
- **B 臂行为记录（非幻觉，但属卡外拼写误用）**：t2 `#empty`、t3 `#retry` 在**属性名位**直接放子位插值 `${()=> … ? 'hidden' : ''}`，k 运行时告警「属性名位不支持插值：绑定将被忽略」——该显隐逻辑实际不生效（`#empty`、`#retry` 恒可见）。因评分器只断言条目数/文本存在性、不断言显隐，未致断言失败，5/5 通过是"通过的是已测契约"。虽零回避（列表均用 For），但这属未生效的条件显隐，忠实记录。
- **一次通过率两臂均为 4/5**，t5 各返工 1 轮；B 首轮无 A 首轮那样的独立失败点（B 首轮 t2/t3 显隐失效不影响断言）。
- **会话 tokens 无法采集**：子代理无 usage 统计，记"—"。代码 token：A 1055 / B 817（tokens.mjs），**B/A = 77.4%**，高于 GLM 的 73.6%、略高于 B3 原口径 76.9%（R2 口径 81.9%），仍显著 <85%。词表卡 token 560/445 与 B3 一致。

### GLM-5.3（2026-08-26，调度式子代理采集）

- **采集方式**：主代理（GLM-5.3，已深度接触 k 源码，不可作被试）派两个零上下文子代理分别作 A/B 臂被试；子代理提示词仅内联词表卡 + 任务卡原文 + 禁用工具（防其检索仓库破坏闭卷条件）。k 不在 GLM-5.3 训练分布（私有仓库、晚于训练截止），子代理不继承主代理对话上下文，被试合法性成立。
- **A 臂 t5 失败明细（返工 1 轮修复）**：① `computed` 使用了但未 import（`computed is not defined`）；② 用 `hidden` 属性隐藏 #err，但 textContent 仍含"邮箱格式错误"，违反任务卡"#err 隐藏时无此文本"约束。返工轮两处一并修复（补 import + `textContent` 置空替代 `hidden`）。
- **协议偏差（后续采集须避免）**：返工提示中除评分器输出原文外附加了断言通过标准说明（原协议仅贴评分器输出 + 一句话），可能省去 1 轮返工。
- **B 臂行为记录**：子代理把 signal 对象直接用作子位插值（`${n}`）与 `For({ each: items })` 的 each 实参——signal 本身是函数，属词表卡"传函数（signal/getter）"的合法形态，**非幻觉**；t2 主动传 `key: 'id'`（与 k-for-require-key lint 建议一致）。零幻觉、零回避。
- **会话 tokens 无法采集**：子代理无 usage 统计，同 baseline 记"—"。代码 token：A 1251 / B 921（tokens.mjs），B/A = 73.6%，低于 B3 的 76.9%（词表卡 token 560/445 与 B3 一致）。
