## 备注（幻觉 API 明细、回避任务明细、异常情况）

### DeepSeek-V4（2026-08-27，调度式子代理采集）

- **采集方式**：主代理（DeepSeek-V4-Flash，已接触 k 材料不可作被试）派两个零上下文子代理分别作 A/B 臂被试；被试提示词仅内联各自词表卡 + 任务卡原文 + 禁用工具（防检索仓库破坏闭卷）。顺序平衡：DeepSeek 为 R2 第 2 个招募家族 → **先 B 后 A**（偶数序）。两会话子代理均为新鲜零上下文，闭卷条件成立。
- **A/B 臂 t5 失败明细（各返工 1 轮，失败根因两臂相同）**：`#err` 先静态内联"邮箱格式错误"，仅依邮箱合法性切换 `hidden`/属性——`hidden` 元素文本仍留在 DOM textContent，导致合法邮箱时 `!text.includes('邮箱格式错误')` 断言失败（"合法邮箱无错误"、"改回合法错误消失"）。返工思路两臂一致：B 臂改 `hidden=${invalid}` 属性绑定 + 子位条件文本；A 臂改 `err.textContent = valid ? '' : '邮箱格式错误'`。**与 GLM-5.3 A 臂 t5 失败模式完全相同**（B3 基线 t4 返工点则不同），提示该断言对"错误文本随状态彻底消失"敏感，是两模型共同易错点。
- **B 臂行为记录（非幻觉，但属卡外拼写误用）**：t2 `#empty`、t3 `#retry` 在**属性名位**直接放子位插值 `${()=> … ? 'hidden' : ''}`，k 运行时告警「属性名位不支持插值：绑定将被忽略」——该显隐逻辑实际不生效（`#empty`、`#retry` 恒可见）。因评分器只断言条目数/文本存在性、不断言显隐，未致断言失败，5/5 通过是"通过的是已测契约"。虽零回避（列表均用 For），但这属未生效的条件显隐，忠实记录。
- **一次通过率两臂均为 4/5**，t5 各返工 1 轮；B 首轮无 A 首轮那样的独立失败点（B 首轮 t2/t3 显隐失效不影响断言）。
- **会话 tokens 无法采集**：子代理无 usage 统计，记"—"。代码 token：A 1055 / B 817（tokens.mjs），**B/A = 77.4%**，高于 GLM 的 73.6%、略高于 B3 原口径 76.9%（R2 口径 81.9%），仍显著 <85%。词表卡 token 560/445 与 B3 一致。

### GLM-5.3（2026-08-26，调度式子代理采集）

- **采集方式**：主代理（GLM-5.3，已深度接触 k 源码，不可作被试）派两个零上下文子代理分别作 A/B 臂被试；子代理提示词仅内联词表卡 + 任务卡原文 + 禁用工具（防其检索仓库破坏闭卷条件）。k 不在 GLM-5.3 训练分布（私有仓库、晚于训练截止），子代理不继承主代理对话上下文，被试合法性成立。
- **A 臂 t5 失败明细（返工 1 轮修复）**：① `computed` 使用了但未 import（`computed is not defined`）；② 用 `hidden` 属性隐藏 #err，但 textContent 仍含"邮箱格式错误"，违反任务卡"#err 隐藏时无此文本"约束。返工轮两处一并修复（补 import + `textContent` 置空替代 `hidden`）。
- **协议偏差（后续采集须避免）**：返工提示中除评分器输出原文外附加了断言通过标准说明（原协议仅贴评分器输出 + 一句话），可能省去 1 轮返工。
- **B 臂行为记录**：子代理把 signal 对象直接用作子位插值（`${n}`）与 `For({ each: items })` 的 each 实参——signal 本身是函数，属词表卡"传函数（signal/getter）"的合法形态，**非幻觉**；t2 主动传 `key: 'id'`（与 k-for-require-key lint 建议一致）。零幻觉、零回避。
- **会话 tokens 无法采集**：子代理无 usage 统计，同 baseline 记"—"。代码 token：A 1251 / B 921（tokens.mjs），B/A = 73.6%，低于 B3 的 76.9%（词表卡 token 560/445 与 B3 一致）。
