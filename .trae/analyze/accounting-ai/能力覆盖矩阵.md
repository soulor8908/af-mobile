# Accounting-AI → aiflow 能力覆盖矩阵

> `--analyze` 阶段一产出 · 依据重构前基线 `2643417`（纯 React 18 实现）
> 目标运行模型：aiflow v2.x（28 组件 + 2 blocks + 运行时原语）
> 判定结论：**业务核可 100% 保留复用；UI 层 7 视图 + App shell 需当新项目重写；能力覆盖具 3 项缺口（均有低成本对策）**

## 4. 缺口清单（3 项 + 1 项组件增强）

### G1 图标系统（缺口）
- 现状：`Icon.tsx` 14 个描边 SVG，`currentColor` 继承。
- 对策：**消费端 data-role + recipes**（不新增组件）。14 个 path 提为 `src/ui/icon.js` 纯函数 `iconSvg(name, size)` 返回 SVG 字符串，UI 层 `html\`${iconSvg(...)}\`` 注入（`${{raw}}` 可信）；SVG 用白名单 class + `data-role` 承载，规避 `no-inline-style`。
- 成本：低（1 个纯函数 + 14 路径迁移，无白名单膨胀）。

### G2 日历自定义格子（部分覆盖）
- 现状：`af-calendar` 只支持单日期选择 + 今天高亮，格子内无法渲染「每日收支/待还点」。
- 对策（二选一）：
  - A. 保留 `af-calendar` 做月份/日期选择骨架，格子内容用 `renderCell` 回调扩展（组件增强）。
  - B. 日历页自建 grid（复用 CalendarView 现有算法），格子走白名单 class + data-role，不依赖 af-calendar。
- 成本：中。**建议 B**（零组件改动，贴合 L4 消费端约束）。

### G3 图表（缺口）
- 现状：`TrendChart.tsx` 纯 SVG 零依赖，`chartExport.ts` SVG→PNG。
- 对策：**提取为框架无关纯函数**放 `core/analytics/chart.js`（返回 SVG 字符串/节点），UI 层 `:bind` 注入。SVG 内 `style` 属性由 `data-role` 承载，规避 `no-inline-style`。
- 成本：低（纯函数迁移，无 react 依赖）。

### G4 af-dialog 命令式 prompt（组件增强）
- 现状：`af-dialog` 支持 slot title/body/footer，但应用层 `dialog.prompt` 需要「标题+输入框+确定/取消」。
- 对策：包一层命令式 helper（非改组件）：`af-dialog` 开放 body slot 放 `<af-field>`，返回 Promise。符合 L4 消费端。
- 成本：低。

- 【可行】披露：业务核可保留，UI 层 7 视图 + shell 重写，3 缺口有对策。
- 【约束落地】重写即启用 L4 全链（ESLint + 白名单三源 + CI），根治「约束不生效」。
