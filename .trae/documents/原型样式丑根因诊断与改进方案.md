# 计划：原型样式"丑"根因诊断 + 改进方案设计

## 目标

验证并确认"框架下 AI 生成的原型样式丑"的根因，产出根因报告 + 分优先级的改进方案设计（**本次不实施框架改动**，方案经用户确认后另行实施）。审美目标已确认：**现代消费级 App**（渐变主视觉、大图卡片、多色层次、视觉锚点，对标小红书/美团/Apple 风）。

## Phase 1 探索结论（已完成）

已读：`prompt/system-prompt.md`、`src/tokens.css`、`src/recipes.css`、`src/atomic.css`、`eslint-plugin-af-mobile/utils/whitelist-v1.json`、真实生成产物 `.workbuddy/基于aiflow-ui开发待办应用/aiflow-todo/src/pages/*.js` + `styles.css`。

### 初步根因清单（待 Phase 2 实测验证）

**B. Prompt 层——只有"合规"指导，零"设计"指导**

| # | 问题 | 证据 |

| B1 | system-prompt 95% 篇幅是禁令/白名单/模式决策树，无任何视觉层级、配色运用、排版节奏、卡片组合的设计指导 | system-prompt.md 全文 |

**C. 修正循环放大器**

AI 任何超出 188 封闭集的视觉尝试 → ESLint error → 回退到最小合规集（card+list+btn+muted 文本）→ 越改越朴素。真实产物 todo 应用证实：全页白/灰 + 单一靛紫品牌色，功能性达标但视觉单调。

## Phase 2 执行步骤：生成演示页实测验证

### 步骤 1：生成诊断用演示页（2 个）

选高视觉需求场景，严格按 system-prompt 规则手工生成（模拟 AI 在该 prompt 下的产出上限）：

- **demo-1 咖啡点单首页**（营销/首页类：品牌主视觉 + 分类 + 推荐商品卡）——验证 hero/大图/色彩/网格的天花板
- **demo-2 商品详情页**（图集 + 价格 + 规格选 + 图文详情）——验证图片/排版/组合能力

生成位置：`.workbuddy/原型样式诊断/`（沿用 .workbuddy 实验目录惯例），单文件 HTML，`<link>` 直引仓库 `src/tokens.css` / `src/recipes.css` / `src/atomic.css`（@layer 纯 CSS 可直引，无需构建）。

生成过程中**逐项记录撞墙点**：尝试渐变头部 → 内联 background-image 被禁令 02 拦截；尝试标签流换行 → 无 wrap class；尝试多彩统计数字 → 只有 4 个文本色；尝试 `padding: 12px 16px` → 无定向间距类。

### 步骤 2：合规校验

跑 `node scripts/lint-flywheel.mjs .workbuddy/原型样式诊断/`，记录演示页中所有违规项及被迫的降级改法（如示例 5 的 wrap 同款问题）。

### 步骤 3：视觉取证

本地起静态服务（`npx serve` 或 python http.server）+ 浏览器截图，保存 2 张演示页截图作为"丑"的客观证据（同时截图 `.workbuddy/.../aiflow-todo` 构建产物做对照，条件允许时）。

### 步骤 4：产出根因报告

汇总为 `.workbuddy/原型样式诊断/根因报告.md`：每条根因附代码位置引用 + 演示页实测撞墙记录 + 截图，区分"能力缺口（A）"与"指导缺失（B）"的贡献权重。

## Phase 3 改进方案设计（审美目标：现代消费级 App）

产出 `.workbuddy/原型样式诊断/改进方案.md`，按优先级分层（实施另行确认）：

### P0-1 补原子类表达力（消除硬缺口，~30 个新 class）

- 定向间距：`px-1..4` / `py-1..4` / `pt-*` / `pb-*`（最小够用集）
- 布局：`wrap`（flex-wrap）、`grid` / `grid-2` / `grid-3`、`min-w-0`、`w-auto`
- 颜色扩展：`text-warn`、`text-gray-*`（灰阶中间档）、`bg-brand-soft` / `bg-danger` / `bg-success` / `bg-warn`、`bg-grad-brand`（品牌渐变）
- 视觉：`border` / `border-brand`、`opacity-*`（60/80）、`aspect-1` / `aspect-4-3` / `aspect-16-9`
- 同步动作：recipes/atomic 定义 + whitelist-v1.json 登记 + `npm run whitelist:check` + prompt 快照 `npm run prompt:check`（AGENTS #8 三源同步）

### P0-2 system-prompt 增加"视觉设计规范"章节

- 视觉层级节拍：hero（渐变主视觉 + display 大标题）→ stats（彩色数字网格）→ 内容卡片组 → cob 操作栏
- 配色运用：60-30-10 原则（中性底 60 / 卡片面 30 / 品牌色+语义色点缀 10），品牌色只用于关键动作与强调
- 图片规范：af-img 用于 banner/商品主图（配 aspect-*），thumb/avatar 混排列表
- 图标规范：统一 24px stroke SVG（附 5-8 个内置 path 示例），**明确禁止 emoji 当图标**
- 每个页面模式附"视觉增强检查清单"（如 page-list 必须有：顶部品牌区或头图、卡片化列表、彩色状态标签）

### P0-3 修复 few-shot 示例（消除错误示范 + 抬高模仿基线）

- 修示例 5 `wrap`、示例 3 `navbar fixed` 两处白名单违规
- 示例 6 profile 重写为"有设计感"版本：渐变 hero 头像卡 + stats-grid 数据条 + 分组 cell 菜单——AI 模仿的基线即达到消费级水准

### P1-1 设计语言升级（tokens/recipes 层）

- hero 配方升级为品牌渐变底（linear-gradient brand→brand-strong + 光晕）而非纯 brand-soft
- 新增高视觉配方 3-5 个：`feature-card`（图标+标题+描述）、`media-card`（大图+文浮层）、`chips`（wrap 标签流容器）、`stat-brand`（品牌色大数字）
- card 恢复可选投影变体 `card-shadow`（保留默认扁平，不破坏现有基线）

### P1-2 场景包最小落地

至少落地"营销/首页"场景包（hero + feature-card + media-card 组合模板），注入 build-prompt.mjs 的需求裁剪逻辑。

### P2 规则松绑评估（供讨论，不默认实施）

- no-inline-style 对 token 合规的渐变（`background-image: linear-gradient(var(--c-brand), var(--c-brand-strong))`）是否放行，或一律走 `bg-grad-*` 原子类（推荐后者，保持封闭集）

### 方案验证标准（实施阶段定义，本次仅写入方案）

- 用改进后体系重新生成 demo-1/demo-2 同需求页面，A/B 截图对比
- 全部 AGENTS §2 自检命令通过（vitest / size / whitelist:check / types:check / prompt:check / aria:check）
- L3 体积预算不超（新增配方走 L2 CSS，需评估 size 影响并按需调整）

- 审美方向锁定"现代消费级 App"；如后续改主意为"克制专业风"，P1-1 的渐变/大图项需重评
