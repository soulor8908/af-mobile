### Seed-Code-v2（2026-08-27，调度式子代理采集，v2 词表卡）

- **采集方式**：主代理派两个零上下文子代理分别作 A/B 臂被试（Seed-Code 家族）。顺序平衡：v2 轮次第 5 个招募家族 → **先 B 后 A**（偶数序）。
- **双臂正式 + 严格口径最终均 28/28 + 6/6 全过，但返工次数多（B 2 轮 / A 1 轮）**——v1 时 Seed-Code 两臂首轮全过、零返工，v2 时暴露出两类新模式错误：
  - **B 臂 t2 `.value=${signal}` 双向绑定被淘汰**：首轮用 `.value=${newText}` 把 input.value 双向绑定到 signal，评分器程序式设置 `input.value = 'foo'` + 触发 keydown 事件时，signal 回写造成 DOM 状态混乱（`Cannot read properties of null (reading 'dispatchEvent')`）。返工 1 轮移除双向绑定、直接 `e.target.value.trim()` 读到本地变量修复。
  - **B 臂 t3 Switch + 模板空白字符陷阱**：把 Switch 写在多行 `html\`…\`` 模板内，Switch 的注释锚点前后引入换行和空格，`#status` 的 textContent 变成 `"\n        加载中\n      "` 而非精确 `"加载中"`。Switch 本身无 bug（单独调过均正常），是多行模板的字面量空白。返工第 2 轮（协议合规追溯返工，见判定章节偏差记录）被试自行诊断出空白根因，改为 `computed` 派生 statusText + `<span id="status">${() => statusText()}</span>` 单响应式文本子节点修复——**被试可自修**。
  - **A 臂 t4 事件监听写在 effect 内（结构错误）**：首轮把 `kw.addEventListener('input', () => keyword.set(kw.value))` 放在 effect body 里（effect 跑一次就结束，没监听上 DOM 事件）。跑起来没报错但 grader `type()` 触发 input 事件后 keyword 没更新，过滤不生效。返工 1 轮（协议合规追溯返工）被试自行把 addEventListener 移出 effect 修复——这是**被试对 effect/DOM 事件的混淆**，属词表卡 API 语义理解偏差，非词表卡反例未覆盖。
- **严格口径（run-strict）双臂 6/6 全过，零假阴性**：B/t2 #empty 用 Show 条件增删（空态显示、有条目时移除节点），B/t3 #retry 用 Show 条件增删（错误态出现、成功/空态移除）——**全部遵循 v2 卡反例指引**，未复现 Qwen-v2 的条件文本模式。
- **t5 空邮箱边界**：两臂均未加 `length > 0` 判断，初始空邮箱即显示错误——与前四个 v2 家族对称一致，确认为任务卡语义边界。
- **代码 token：A 1150 / B 1045，B/A = 90.9%**。v2 轮五家族均值：(94.3% + 84.1% + 89.3% + 83.2% + 90.9%) / 5 = **88.4%**，较 v1 轮五家族均值 ~76% 上升约 12pp。
- **B 臂风格亮点（非幻觉，属风格选择）**：t3 首轮是 v2 轮唯一用 Switch 的实现（其他四家都用 `() => status() === '...' ? ... : ''` 条件表达式），返工后改为 computed+条件文本；t5 用 Show 条件增删 #err（而非条件文本），语义最严格；t4 用 computed 派生过滤。零幻觉、零回避。
- **异常**：双臂返工次数多（3/10 任务），但都是**结构错误**而非幻觉或 API 越权，且被试单轮自修路径清晰——v2 卡的 API 语义示例对 Seed-Code 这类偏底层被试不够明确（effect 与事件监听的职责边界），但 run.mjs 无「effect 内加事件监听禁止」的断言，属评分器风格层面。
