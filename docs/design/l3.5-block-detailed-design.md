## 0. 概述:L3.5 的位置与三层颗粒度

### 0.1 五层分层对照(在现有四层基础上插入 L3.5)

| 层 | 内容 | 防护方式 | 阻断位置 |
|---|---|---|---|
| L1 | Token(58 变量) | `no-token-modification` + `no-inline-style` | ESLint error |
| L2 | 配方 102 + 原子 52 = 154 class | `token-whitelist` + `no-recipe-break` | ESLint error/warn |
| L3 | 20 个 af-* 原子组件(WC) | `wc-light-no-style` + `wc-shadow-use-token` + `wc-aria-required` 等 | ESLint error |
| **L3.5** | **42 个 Block 复合组件(WC)** | **`wc-block-states` + `wc-block-props-count` + `wc-block-no-internal-ref` 等** | **ESLint error** |
| L4 | AI 约束层 | Prompt + ESLint 兜底 + CI | 三层防线 |

**决策 D8**:L3.5 独立目录 `src/blocks/` + 独立 `wc-block-*` 规则集,与 L3 原子层职责分离,便于预算/规则/prompt 独立管理。

### 0.2 三层颗粒度

```
Page 层    5 个槽位(header / content / tab / float / footer)
   ↓  AI 分配 Block 到槽位
Block 层   42 个 Block × 2-3 variant  ← 主战场,AI 只写这层
   ↓  Block 内部用 Atomic 组合(库作者维护,AI 不可见)
Atomic 层  20 个 af-* + 154 class(不暴露给 AI)
```

### 0.3 Block 颗粒度上下限

| 维度 | 上限 | 下限 | 超限处理 |
|---|---|---|---|
| 单 Block AI 输出 token | ~80 | ~20 | 超过 80 拆 Block;低于 20 合并 |
| 单 Block 内部行数 | ~60 | ~15 | 超过 60 拆两个 Block |
| 单 Block props 数 | 5 | 2 | 超过 5 拆 Block;少于 2 合并 |
| Block 总数 | 50 | 30 | 超过 50 AI 选择困难;低于 30 覆盖不足 |

**决策 D1**:Block 颗粒度上限 60 行/80 tokens/5 props;下限 15 行/20 tokens/2 props。超过上限退化为代码生成,失去约束意义。

### 0.4 Block = production-grade 最小可信单元

区别于 DesignGUI(只做 token 压缩),aiflow-ui Block 内部强制包含:

1. **五态完整**:idle / loading / error / empty / success
2. **a11y 内置**:aria-label / aria-live / 焦点顺序 / 键盘导航
3. **移动端适配**:viewport / 安全区 / 键盘弹起 / 触摸热区 44px
4. **边界处理**:超长文本截断 / 空数据 / 网络断开 / 重试

**决策 D2**:Block 强制五态 + a11y + 移动端适配,这是区别 DesignGUI 的质量保证层,是 production-grade 的核心。

## 1. Block 协议规范

### 1.1 命名

格式:`af-{domain}-{form|grid|list|group|card|header|nav|action|...}`,全小写连字符。

| 正例 | 反例 |
|---|---|
| `af-auth-form` | `af-AuthForm`(大写) |
| `af-product-grid` | `af-productGrid`(驼峰) |
| `af-setting-group` | `af-settings`(过泛) |

### 1.2 基类

Block extends `AfElement`,沿用现有基类的 5 生命周期 + defineProp + emit + escapeHtml + html + i18n 自动应用。

```javascript
import { AfElement, html } from '../lib/af-element.js';

export class AfAuthForm extends AfElement {
  static useShadow = false;  // 默认 Light DOM,复用 recipe class
  // ...
}
```

**useShadow 选择原则**:
- Light DOM(默认):复用 L2 recipe class,内部用 `data-role` 钩子,受 `wc-light-no-style` 约束
- Shadow DOM:仅当需要样式强隔离时(如 `af-toast-stack` 全局浮层),CSS 必须用 `var(--*)`,受 `wc-shadow-use-token` 约束

### 1.3 属性契约

用 `AfElement.defineProp` 声明,类型限 `String/Number/Boolean/Array/Object`。每个 Block props 数 2-5。

```javascript
AfElement.defineProp(AfAuthForm.prototype, 'variant', { type: String, default: 'phone-code' });
AfElement.defineProp(AfAuthForm.prototype, 'title', { type: String, default: '' });
AfElement.defineProp(AfAuthForm.prototype, 'submitUrl', { type: String, attr: 'submit-url' });
AfElement.defineProp(AfAuthForm.prototype, 'agreement', { type: String, default: '' });
AfElement.defineProp(AfAuthForm.prototype, 'loading', { type: Boolean, default: false });
```

### 1.4 variant 机制

单 `variant` 属性,枚举值,内部 `onAttributeChange` 切换渲染模板。参考现有 `af-skeleton-page` 的 4 变体模式。

```javascript
onAttributeChange(name) {
  if (name === 'variant') this._render();
}
```

variant 枚举必须在文档化,ESLint `wc-block-variant-enum` 检测 `variant` setter 是否限制枚举。

### 1.5 事件契约

格式 `af-{block}:{action}`,emit 含 `bubbles: true, composed: true`(沿用 AfElement.emit)。事件 detail schema 必须文档化。

```javascript
this.emit('success', { token: 'xxx', user: {...} });
this.emit('error', { msg: '手机号格式错误', field: 'phone' });
```

### 1.6 状态完整性 checklist(强制)

每个 Block 必须实现以下五态,ESLint `wc-block-states` 检测:

- [ ] **idle**:初始态,无数据无加载
- [ ] **loading**:数据获取中,显示骨架屏/spinner
- [ ] **error**:错误态,显示错误信息 + 重试按钮
- [ ] **empty**:空数据态,显示空提示
- [ ] **success**:成功态,正常渲染数据

a11y 内置清单:
- [ ] 所有可交互元素有 `aria-label` 或可见 label
- [ ] 异步状态变化用 `aria-live="polite"` 通知
- [ ] 模态类 Block 实现焦点陷阱 + 焦点还原(沿用 `AfElement.lockScroll`)
- [ ] 列表类 Block 支持 ArrowUp/Down + Enter 键盘导航

移动端适配清单:
- [ ] 触摸热区 ≥ 44×44px
- [ ] 安全区 padding:`padding-bottom: env(safe-area-inset-bottom)`
- [ ] 输入类 Block 处理键盘弹起(viewport 滚动)
- [ ] `prefers-reduced-motion` 覆盖动画

### 1.7 内部组合规则

Block 内部只能用:
- 现有 20 个 `af-*` 原子组件
- L2 recipe class(154 白名单)
- `data-role` 属性做内部钩子

禁止:
- 裸 `<div>` + inline style(继承 `wc-light-no-style`)
- 引入新 class(若必须新增走三源同步,见 §8.1)
- 修改 af-* 源码(Block 只组合,不改原子)

### 1.8 不暴露原则

Block 内部结构对 AI 不可见。AI 只看到:标签 + props + 事件。内部 ref 一律用 `data-role`。

**AI 代码禁止**:
- `document.querySelector('af-auth-form > div')` —— 禁止穿透 Block 边界
- `blockInstance.shadowRoot.querySelector(...)` —— 禁止访问内部
- 修改 Block 内部 DOM —— 必须通过 props/事件

ESLint `wc-block-no-internal-ref` 检测消费端代码,违反即 error。

## 2. Block 内部交互逻辑归属

### 2.1 四类逻辑的归属

| 逻辑类型 | 谁写 | 形态 | AI token 成本 |
|---|---|---|---|
| **Block 内部交互**(倒计时/校验/loading/虚拟滚动) | 库作者 | Block 类方法 | 0(AI 不写) |
| **Block 间协调**(登录后跳转/列表筛选联动) | AI | `on-*` 声明式字符串 | ~5 tokens/事件 |
| **页面级数据编排**(fetch+处理+多 Block 分发) | AI | definePage.transform 纯函数 | ~80 tokens |
| **业务定制**(手势/拖拽/第三方 SDK) | AI | `<script>` addEventListener | 按需,少数场景 |

90% 交互落在前两类,AI 几乎不写 JS。剩下 10% 落第四类——这时 AI 写的是事件监听器,不是从零写交互。

### 2.2 Block 内部交互示例(库作者写)

```javascript
// src/blocks/af-auth-form.js(库源码,AI 永远不写)
export class AfAuthForm extends AfElement {
  static useShadow = false;

  mounted() {
    this._buildShell();
    this._bindEvents();
  }

  _bindEvents() {
    const codeBtn = this.$('[data-role=code-btn]');
    const form = this.$('[data-role=form]');
    codeBtn.addEventListener('click', () => this._startCountdown());
    form.addEventListener('submit', (e) => this._handleSubmit(e));
  }

  _startCountdown() {
    const phone = this.$('[data-role=phone]').value;
    if (!/^1\d{10}$/.test(phone)) {
      this.emit('error', { msg: '手机号格式错误', field: 'phone' });
      return;
    }
    let s = 60;
    const btn = this.$('[data-role=code-btn]');
    btn.disabled = true;
    const t = setInterval(() => {
      btn.textContent = `${s}s 后重试`;
      if (--s < 0) {
        clearInterval(t);
        btn.disabled = false;
        btn.textContent = '获取验证码';
      }
    }, 1000);
    this._cleanups = this._cleanups || [];
    this._cleanups.push(() => clearInterval(t));
  }

  async _handleSubmit(e) {
    e.preventDefault();
    this.loading = true;
    try {
      const res = await fetch(this.submitUrl, { method: 'POST', body: new FormData(this.$('[data-role=form]')) });
      this.emit(res.ok ? 'success' : 'error', await res.json());
    } catch (err) {
      this.emit('error', { msg: '网络错误' });
    } finally {
      this.loading = false;
    }
  }

  unmounted() {
    this._cleanups?.forEach(c => c());
  }
}
```

### 2.3 Block 间协调(on-* 声明式字符串)

```html
<af-auth-form
  variant="phone-code"
  submit-url="/api/login"
  on-success="redirect:/home"
  on-error="toast:$msg"
></af-auth-form>
```

`on-*` 接受的指令格式(白名单):

| 指令 | 含义 | 翻译 |
|---|---|---|
| `redirect:/path` | 跳转路由 | `router.go('/path')` |
| `toast:$msg` | 显示 toast | `af-toast.show({ msg: detail.msg })` |
| `setState:key=val` | 设置 state | `state.key = val` |
| `action:fnName` | 调用 definePage action | `actions.fnName(detail)` |
| `dialog:dialogId` | 打开 dialog | `document.getElementById(dialogId).open()` |

**决策 D3**:`on-*` 只接受声明式字符串,不接受 JS 表达式。否则退化为写 JS,约束面塌。

### 2.4 页面级数据编排

见 §3.4 transform 原语。AI 写纯函数,把接口数据映射到 Block props schema。

### 2.5 业务定制(少数场景)

AI 在 `<script>` 里写 `addEventListener`,ESLint `wc-no-addeventlistener` 检测:消费端禁止裸 addEventListener,必须走 effects 或 `@event` 绑定。**例外**:仅当 effects 白名单无法覆盖的事件类型(如第三方 SDK 回调)允许,需加 `// eslint-disable-next-line wc-no-addeventlistener` 显式声明理由。

## 3. definePage 原语规范

8 个原语,覆盖 React/Vue 13 项必备能力。

### 3.1 React/Vue/Svelte 能力对照

| 能力 | React | Vue | Svelte | aiflow-ui | 必备 |
|---|---|---|---|---|---|
| 组件内状态 | useState | ref | $state | state | ✅ |
| 跨组件状态 | Context+useReducer | Pinia | store | state(全局引用) | ✅ |
| 副作用 | useEffect | watch | $effect | effects | ✅ |
| 派生计算 | useMemo | computed | $derived | computed | ✅ |
| 生命周期 | useEffect[] | onMounted | $effect | effects.mount/unmount | ✅ |
| 双向绑定 | 受控组件 | v-model | bind: | :model + @change | ✅ |
| 跨组件通信 | Context/事件 | emit/provide | emit | state + computed | ✅ |
| 错误边界 | ErrorBoundary | errorCaptured | - | onError | ✅ |
| 过渡动画 | CSSTransition | Transition | transition | transition | ✅ |
| 组件缓存 | - | KeepAlive | - | keepAlive | ✅ |
| 数据获取 | SWR/React Query | useFetch | - | af-data + fetchPage | ✅(已有 fetch.js) |
| 路由 | react-router | vue-router | sveltekit | router.js | ✅(已有) |
| 内容分发 | children | slot | slot | Web Component slot | ✅(已有) |

### 3.2 definePage 完整签名

```javascript
import { definePage } from '@af-mobile/ui';

definePage({
  state,        // 1. 状态声明
  computed,     // 2. 派生计算(纯函数,自动依赖追踪)
  effects,      // 3. 副作用(白名单订阅)
  transform,    // 4. 数据变换(纯函数)
  actions,      // 5. 状态变更(纯函数)
  onError,      // 6. 错误边界
  transition,   // 7. 页面过渡
  keepAlive,    // 8. 缓存策略
});
```

### 3.3 state(对应 useState / ref)

声明式字段,内部转 `signal`。引用全局 state 用 `state.cart` 语法。

```javascript
definePage({
  state: {
    tab: 'all',
    loading: false,
    cart: [],          // 引用全局 state.cart
    form: { phone: '', code: '' },
  },
});
```

**实现**:page.js 内部把每个字段转成 `signal`,赋值时调 `signal.set`。全局 state 是独立 signal 实例,页面 state 引用即读取。

**ESLint**:`wc-state-schema` 检测 state 字段必须声明类型(注释或 JSDoc)。

### 3.4 computed(对应 useMemo / computed)

纯函数,**自动依赖追踪**。复用 `state.js` 的 `_cur` 注入机制,AI 不写 deps 数组。

```javascript
definePage({
  computed: {
    total:    () => state.cart.reduce((s, i) => s + i.price, 0),
    filtered: () => state.list.filter(i => i.tab === state.tab),
    cartCount: () => state.cart.length,
  },
});
```

**实现**:每个 computed 调用 `state.js` 的 `computed(fn)`。`_cur` 在 fn 执行时注入,自动建立依赖图。

**与 React/Svelte 对照**:
- React `useMemo(fn, [deps])` —— 必须手动写 deps,AI 漂移高发区
- Svelte `$: doubled = count * 2` —— 语法糖,语义模糊(派生+副作用混用)
- aiflow-ui `computed: { doubled: () => state.count * 2 }` —— 自动追踪,无歧义

**ESLint**:`wc-pure-function` 检测 computed 函数体无副作用(无赋值外部、无 fetch、无 DOM 操作)。

### 3.5 effects(对应 useEffect / watch)

白名单 key,不接受任意 `addEventListener`。

```javascript
definePage({
  effects: {
    mount:    () => fetchList(),                          // 进入页面
    unmount:  () => clearTimer(),                         // 离开页面
    route:    (params) => fetchList(params.id),           // 路由参数变化
    online:   (e) => state.loading = !e.offline,          // 网络变化
    visible:  (e) => e.hidden || refresh(),               // 页面可见性
    storage:  ['cart', (v) => state.cart = v],            // storage 同步
    interval: [60000, () => refresh()],                   // 定时
    resize:   (e) => adjustLayout(e.width),               // 视口变化(横竖屏)
  },
});
```

**白名单 key**(完整):`mount` / `unmount` / `route` / `online` / `offline` / `visible` / `hidden` / `storage` / `interval` / `resize` / `themechange` / `localechange`。

**实现**:page.js 内部用 `effect(fn)` 包裹,白名单 key 对应预定义的 EventTarget 订阅。

**与 React/Svelte 对照**:
- React `useEffect(fn, [deps])` —— deps 数组漂移
- Svelte `$effect(() => { ... })` —— 无白名单,任意副作用
- aiflow-ui `effects: { mount: fn }` —— 白名单收敛,可静态分析

**ESLint**:`wc-effects-whitelist` 检测 effects key 只能在白名单内;`wc-no-addeventlistener` 检测消费端禁止裸 addEventListener。

### 3.6 transform(纯函数,数据变换)

接口数据 → Block props schema。**AI 必写**,这是业务逻辑,无法声明式表达。

```javascript
definePage({
  transform: (raw) => ({
    products: raw.list
      .filter(p => p.status !== 'offline')
      .map(p => ({
        id: p.id,
        title: p.goods_name,
        price: (p.price_cents / 100).toFixed(2),
        image: p.img_url,
      })),
    total: raw.count,
    filters: raw.filters,
  }),
});
```

**约束**:必须是纯函数,无副作用。输入 raw,输出匹配下游 Block props 的 schema。

**ESLint**:`wc-transform-pure` 用 AST 检测 transform 函数体无 `fetch` / `document` / `window` / 外部赋值。

### 3.7 actions(对应 reducer)

纯函数状态变更。

```javascript
definePage({
  actions: {
    switchTab: (t) => state.tab = t,
    addToCart: (item) => state.cart.push(item),
    removeFromCart: (id) => state.cart = state.cart.filter(i => i.id !== id),
  },
});
```

**实现**:actions 内部赋值触发 signal.set,自动通知 computed 重算和 :bind 下发。

**ESLint**:`wc-pure-function` 检测 actions 只能赋值 state 字段,不能有其他副作用。

### 3.8 onError(对应 ErrorBoundary / errorCaptured)

```javascript
definePage({
  onError: (err, ctx) => {
    reportError(err);
    if (ctx.block === 'product-grid') {
      document.querySelector('af-product-grid').setAttribute('variant', 'error');
    }
    if (err instanceof TimeoutError) afToast.show({ msg: '请求超时' });
    if (err instanceof HttpError && err.status === 401) router.go('/login');
  },
});
```

**ctx 字段**:`{ block, source, url, retry }`。block 是出错的 Block 标签名,source 是 'fetch'/'action'/'effect',url 是请求 URL,retry 是重试函数。

**实现**:page.js 用 try-catch 包裹 af-data fetch 和 action 调用,错误统一进 onError。

### 3.9 transition(对应 Transition)

枚举 `slide` / `fade` / `none`。透传 `router.js` 的 `startViewTransition`。

```javascript
definePage({
  transition: 'slide',
});
```

**实现**:page.js 把 transition 透传给 `route(path, handler, { transition })`。router.js 已有 `document.startViewTransition` 调用。

### 3.10 keepAlive(对应 KeepAlive)

```javascript
definePage({
  keepAlive: {
    enabled: true,
    save:    () => ({ scrollTop: window.scrollY, tab: state.tab }),
    restore: (saved) => {
      window.scrollTo(0, saved.scrollTop);
      state.tab = saved.tab;
    },
  },
});
```

**实现**:透传 `router.js` 的 `keepAlive: true` 路由选项 + save/restore 钩子。router.js 已有 `_cache` Map 缓存机制。

## 4. af-data 数据源 + :bind 数据绑定

### 4.1 设计决策

**决策 D4**:af-data 和 :bind 是 definePage 的语法糖,内部由 page.js 调度,对 AI 暴露单一 definePage 入口。AI 只学一个 API。

内部实现分三个文件(职责清晰、可独立测试):
- `src/lib/page.js` —— definePage 运行时(状态/副作用/派生/生命周期调度)
- `src/lib/bind.js` —— :bind / @event / :model 解析
- `src/lib/data.js` —— af-data controller(封装 fetchPage + transform + 状态同步)

但 AI 只需了解 `definePage` 一个 API,`:bind` 和 `af-data` 作为它的语法糖。

### 4.2 `<af-data>` 标签

```html
<af-data src="/api/products" ref="ds"></af-data>

<af-page-header variant="search" title="商品列表" :count="ds.total"></af-page-header>
<af-tabs :tabs="ds.filters"></af-tabs>
<af-product-grid :items="ds.products" :total="ds.total"></af-product-grid>
```

**属性**:
- `src`:接口 URL,触发 `fetchPage`
- `ref`:数据源引用名,供 `:bind` 引用
- `transform`(可选):变换函数名,引用 definePage.transform;若不指定用 definePage.transform 字段
- `loading`(自动):内部 loading 状态自动同步到 `definePage.state.{ref}Loading`
- `error`(自动):内部 error 状态自动同步到 `definePage.state.{ref}Error`

**实现**:data.js 内部调 `fetchPage(src, opts)`,结果经 transform 处理后存入 signal,错误类型(Timeout/Http/Abort)透传到 `definePage.onError`。

### 4.3 `:bind` 语法

单向绑定:`:items="ds.products"` —— 把 ds 数据源的 products 字段绑定到 Block 的 items 属性。

```html
<af-product-grid :items="ds.products" :total="ds.total"></af-product-grid>
```

**实现**:bind.js 解析 `:bind` 表达式,建立 `signal → Block.setAttribute` 的响应式管道。signal 变化时自动 setAttribute。

**ESLint**:`wc-bind-syntax` 检测 `:bind` 只能绑定到 `definePage.state` / `definePage.computed` / `af-data` ref 字段。

### 4.4 `@event` 事件绑定

```html
<af-auth-form @success="actions.onLoginSuccess" @error="actions.onLoginError"></af-auth-form>
```

`@event="actions.fnName"` —— Block emit event 时调用 definePage.actions.fnName(detail)。

也支持声明式指令(§2.3):

```html
<af-auth-form @success="redirect:/home" @error="toast:$msg"></af-auth-form>
```

### 4.5 `:model` 双向绑定

```html
<af-auth-form :model="form" @change="actions.onFormChange"></af-auth-form>
```

Block emit `change` 事件 → framework 写回 `state.form` → 重新下发到 Block `:model`。

替代 Vue `v-model` 和 Svelte `bind:`,但显式分离数据流(AI 易追踪)。

### 4.6 transform 挂载点

二选一:

```html
<!-- 方式 A:af-data 上指定 transform 函数名 -->
<af-data src="/api/products" ref="ds" transform="transformProducts"></af-data>
```

```javascript
// 方式 B:definePage.transform 字段
definePage({
  transform: (raw) => ({ products: raw.list, total: raw.count }),
});
```

方式 B 适合单数据源页面;方式 A 适合多数据源页面(每个 af-data 独立 transform)。

## 7. ESLint 规则集

### 7.1 新增规则(写入 `eslint-plugin-aiflow/rules/`)

#### `wc-block-states`(error)

**意图**:Block 必须实现五态。

**检测**:扫描 Block 类的 mounted/render 方法,检测是否包含 loading/error/empty 分支(通过字符串匹配 `loading`/`error`/`empty` + 条件渲染)。

**正例**:
```javascript
_render() {
  if (this.loading) return this._renderLoading();
  if (this._error) return this._renderError();
  if (!this._data?.length) return this._renderEmpty();
  return this._renderSuccess();
}
```

**反例**:
```javascript
_render() {
  return this._data.map(i => `<div>${i}</div>`).join('');  // 无五态
}
```

#### `wc-block-props-count`(error)

**意图**:Block props 数 2-5。

**检测**:统计 `AfElement.defineProp` 调用数。

#### `wc-block-no-internal-ref`(error)

**意图**:AI 代码禁止穿透 Block 边界访问内部。

**检测**:在消费端代码(非 src/blocks/)中检测 `querySelector('af-* > ...')` 和 `blockInstance.shadowRoot`。

**正例**:
```javascript
document.querySelector('af-auth-form').setAttribute('loading', 'true');
```

**反例**:
```javascript
document.querySelector('af-auth-form > div > input').value = '...';
blockInstance.shadowRoot.querySelector('input');
```

#### `wc-effects-whitelist`(error)

**意图**:effects key 只能在白名单。

**白名单**:`mount`/`unmount`/`route`/`online`/`offline`/`visible`/`hidden`/`storage`/`interval`/`resize`/`themechange`/`localechange`。

**检测**:扫描 `definePage({ effects: {...} })` 的 key。

#### `wc-transform-pure`(error)

**意图**:transform 函数体无副作用。

**检测**:AST 分析 transform 函数体,禁止 `fetch`/`document`/`window`/外部赋值/方法调用(除 map/filter/reduce/Object.assign/解构)。

**正例**:
```javascript
transform: (raw) => ({
  products: raw.list.filter(p => p.status !== 'offline').map(p => ({ ... })),
})
```

**反例**:
```javascript
transform: (raw) => {
  document.title = raw.title;  // 副作用
  fetch('/log', { method: 'POST' });  // 副作用
  return raw;
}
```

#### `wc-bind-syntax`(error)

**意图**:`:bind` 只能绑定到 definePage.state / computed / af-data ref 字段。

**检测**:解析 HTML `:bind` 表达式,验证右侧是 `state.xxx` / `computed.xxx` / `{ref}.xxx` 形式。

#### `wc-no-addeventlistener`(error)

**意图**:消费端禁止裸 addEventListener,必须走 effects 或 @event。

**检测**:扫描消费端代码(非 src/)的 `addEventListener` 调用。例外:有 `// eslint-disable-next-line wc-no-addeventlistener` 注释且理由充分。

#### `wc-definepage-single`(error)

**意图**:每页只允许一个 definePage 调用。

**检测**:统计单文件内 `definePage(` 调用数 ≤ 1。

#### `wc-block-variant-enum`(warn)

**意图**:variant 属性必须限制枚举值。

**检测**:Block 类的 variant setter 或 onAttributeChange 必须校验枚举。

#### `wc-state-schema`(error)

**意图**:definePage.state 字段必须声明类型(注释或 JSDoc),便于静态分析与 AI 生成。

**检测**:扫描 `definePage({ state: {...} })` 的每个字段,要求同行或上方有 `// {Type}` 注释或 JSDoc `@type`。

**正例**:
```javascript
state: {
  tab: 'all',        // String
  loading: false,    // Boolean
  cart: [],          // Array<Item>
  form: { phone: '', code: '' }, // Object
},
```

**反例**:
```javascript
state: {
  tab: 'all',    // 无类型注释
  cart: [],
},
```

#### `wc-pure-function`(error)

**意图**:definePage.computed 和 definePage.actions 必须是纯函数(无 fetch/DOM/外部赋值)。

**检测**:AST 分析 computed/actions 函数体,禁止 `fetch`/`document`/`window` 调用,禁止赋值外部变量(actions 仅允许赋值 `state.*` 字段)。

**与 `wc-transform-pure` 区别**:`wc-transform-pure` 管 transform,`wc-pure-function` 管 computed/actions。

## 8. 与现有体系的衔接

### 8.1 与 L1/L2

- Block 内部用 recipe class + token,不新增 class
- **决策 D5**:Block 用 `data-role` 不膨胀白名单,复用现有 `wc-light-no-style` 模式,零白名单成本
- 若必须新增 class,走三源同步:`src/recipes.css` 定义 + `whitelist-v1.json` 登记 + `system-prompt.md` 注入(`build-prompt.mjs` 自动)

### 8.2 与 L3

- Block 组合 af-*,不修改 af-* 源码
- af-list/af-tabs 等已有复合行为的**保持 L3 不重分类**(它们是原子层的高级原子,Block 是更大粒度的组合)
- Block 内部可调用 af-* 的属性和事件,但不穿透 shadowRoot

### 8.3 与 L4

- Block 标签加入 system-prompt 的 L3.5 Block 简表(42 个,每个一行)
- wc-block-* 规则加入 recommended config
- 白名单 v1 不膨胀(Block 用 data-role)
- AI 修正流程(L4 §4)不变,wc-block-* 规则纳入自动修正 3 轮

### 8.4 与 router.js

- `definePage.keepAlive.enabled` → 透传 `route(path, handler, { keepAlive: true })`
- `definePage.transition` → 透传 `route(path, handler, { transition })`,router.js 已有 `document.startViewTransition`
- `definePage.keepAlive.save/restore` → router.js 的 `_cache` 已缓存 DOM,save/restore 是页面 state 的保存恢复(在 page.js 实现,不动 router.js)
- `effects.route` → 订阅 `router.current()` 变化

### 8.5 与 state.js

- definePage 内部全用 `signal`/`computed`/`effect`,不引入新响应式原语
- **决策 D6**:复用 state.js,自动依赖追踪已有(`_cur` 注入机制)
- state 字段 → 内部 signal 实例
- computed → 直接调 `computed(fn)`
- effects → `effect(fn)` 包裹 + 白名单 EventTarget 订阅

### 8.6 与 fetch.js

- af-data 内部调 `fetchPage(url, opts)`
- 错误类型(`TimeoutError`/`HttpError`/`AbortError`)透传到 `definePage.onError`
- `fetchPage` 的 cache/dedupe/retry 选项透传到 `<af-data cache="true" retries="3">`

### 8.7 与 af-element.js

- Block extends `AfElement`,沿用 `defineProp`/`emit`/`escapeHtml`/`html`/`mounted`/`unmounted`/`onAttributeChange`/`static i18n`/`lockScroll`
- Block 不重写 connectedCallback/disconnectedCallback(基类已处理 _mounted 标志 + theme/locale 订阅)

### 8.8 与 i18n.js / theme.js

- Block 用 `static i18n` 映射表,沿用基类 `_applyI18n`
- definePage.effects 不直接处理 i18n/theme,通过 `state.locale`/`state.theme` 响应(全局 state 订阅 localechange/themechange 事件)

| ID | 决策 | 章节 | 理由 |
|---|---|---|---|
| D1 | Block 颗粒度上限 60 行/80 tokens/5 props | §0.3 | 超过退化为代码生成,失去约束意义 |
